# 版本与兼容

NeverSSH 不安装远端服务。远端 Python 源码由本地包提供，首次连接写入内容寻址的构建缓存，后续连接复用。

## 0.7.0 客户端升级

工作区的读取、写入、编辑、上传和下载现在需要显式确认规则。收到 `WORKSPACE_RULES_CHANGED` 后，客户端应先展示完整规则，待阅读后，把同一响应给出的 `workspace_rules_ack` 作为参数加入原调用。旧客户端如果只重发原调用，会再次收到规则提示。即使首次响应丢失，被暂停的读取也不返回文件正文，被暂停的下载也不创建目的文件。打开工作区和运行 Bash 会展示规则，文件操作的确认单独记录。重新打开工作区后，需要重新确认适用规则。图片响应的 9 MiB 上限单独计算。

并发检查同一目录时，如果收到 `WORKSPACE_RULES_RETRY`，使用原工作区 ID 重试即可。工具会先核对最新规则，再决定是否访问文件。

远端 HOME 位于 NFS 时，修复了回收旧构建、重装损坏缓存和清理过期命令归档时报“目录非空”的问题。这些操作已在 Linux 的 NFSv4.1 挂载上验证。

单文件 Bash 查看命令的标准输出为零字节时，不会建立读取记录。要整体替换空文件，可先用 `ssh_read_file` 读取。单文件搜索只有在交付的预览包含文件正文时才建立读取记录，预览可以截断。无匹配仍是有效的搜索结果，后续编辑前仍需读取文件。文本分页超过 256 KiB 时，客户端应调小 `limit` 或通过 `ssh_bash` 搜索。从任何 `offset` 起读到末尾，若剩余正文超过该上限，工具会返回整文件分页提示。

## 0.6.0 客户端升级

`ssh_read_file` 已移除 PDF 渲染和 `pages` 参数。升级时，原先读取 PDF 的调用应改用远端已有的 PDF 工具。例如，远端安装了 `pdftotext` 时，可通过 `ssh_bash` 运行 `pdftotext report.pdf -` 提取正文。

## 0.5.0 客户端升级

打开工作区时最多显示 50 项 Git 状态，超出时给出省略项数和查看完整列表的命令。工作区写入、编辑和上传遇到新增、变更或删除的适用规则时，先返回 `WORKSPACE_RULES_CHANGED` 和规则变化。客户端阅读后可重试该操作。读取、下载和 Bash 继续随结果交付规则。

读取超过 256 KiB 的文本时，客户端应通过 `offset` 和 `limit` 获取各页。在 `0.5.0` 中，笔记本和 PDF 的一次读取可包含多个文本块和图片块，客户端应按顺序显示。该版本的 PDF 渲染需要远端 Poppler。精确编辑成功会返回带行号的修改片段。

`ssh_bash` 的前台等待上限为 600 秒，任务查询仍为 300 秒。要使用最长等待，客户端工具调用超时应至少为 660 秒。

## 0.4.0 文件读取与本地传输

`ssh_read_file` 无需新增必填参数，可按文件内容识别 PNG、JPEG、GIF 和 WebP，并直接返回原生 MCP `image` 内容块。图片完整返回，`offset` / `limit` 只作用于文本；SVG 仍为 UTF-8 文本，其他二进制仍返回文本错误。图片受既有 `maxFileBytes` 限制，包含附带规则的 MCP 结果另受 9 MiB 的序列化大小限制；超限返回文本错误，保留连接，不截断图片或规则。图片读取不依赖 SFTP，也不落成本地文件；显示需要客户端支持 MCP 图片。其他工具仍只返回可读文本，所有工具都不提供 `structuredContent` 或 `outputSchema`。

项目开发默认直接使用远端读取、写入、编辑和 Bash 工具；查看图片无需本地下载，普通修改也不以本地临时文件加上传作为默认流程。上传下载继续用于具体的传输需求。

`ssh_upload` 和 `ssh_download` 每次通过 `localPath` 指定本机绝对路径，无需预先配置目录。省略 `localTransferRoots` 或设置为 `[]` 时不限制本地目录；空列表不再表示禁用传输。非空列表继续限制本地真实路径，符号链接不能逃出配置范围。`localPath` 不按远端工作区或 `cwd` 解析。

普通文件、大小、覆盖、原子提交和取消检查保持不变，下载目标仍拒绝符号链接。配置版本保持 `1`。

## 0.3.1 接口调整

`0.3.1` 将所有 MCP 工具统一为可读文本，不再提供 `structuredContent` 或 `outputSchema`。已有工具的参数、文本格式和远端执行行为保持兼容；依赖结构化结果的程序调用方需要改为读取文本内容。

远端项目新增工作区打开和 skill 读取工具，共 15 个工具。Bash、文件和传输支持互斥的 `connection_id` / `workspace_id`，原有连接模式继续可用；两种 scope 的互斥由运行时校验，公开 schema 保持普通对象形式。工作区句柄只属于当前 MCP 实例和连接，不持久化或自动恢复，也不会把本地客户端的 skill 同步到远端。

在 `0.3.1` 中，工作区文件、传输和 Bash 操作自动在结果中返回适用规则的增量，不再因规则未读或变化而要求先刷新上下文。提示返回时，文件操作已经执行，命令已经启动；规则指导后续操作。恢复根上下文或重新发现 skill 使用再次 `ssh_workspace_open`；相同连接、根目录和配置可复用句柄，但重置规则交付记录并重建 skill 目录。打开不遍历子目录规则，后续目标操作会自动返回适用规则。Bash 只发现 `cwd` 的规则，连接模式不加载项目上下文；原有路径和文件版本检查继续生效。

skill 默认只从工作区根目录的 `.agents/skills`、`.claude/skills` 发现，不支持随目标路径发现子目录 skill。`skill_directories` 中的相对目录以工作区根解析一次，显式绝对路径和 `~/` 仍可指定共享或个人目录。进入子目录不会扩大 skill 搜索范围；`AGENTS.md` 继续按目标路径收集。

`ssh_skill_read` 使用目录返回的 `skill_name`。唯一名称可直接调用，名称冲突时用 `project@check`、`shared@check` 等短目录前缀区分，必要时加短后缀。当前打开期间目录保持不变。名称不可用时重新打开工作区，以新目录为准；重新打开可能分配不同名称。

## 版本维度

| 维度 | 当前值 | 兼容规则 |
| --- | --- | --- |
| MCP 服务版本 | `0.7.0` | `0.x` 阶段不兼容接口调整升 minor；`1.0` 起按 semver 升 major |
| worker 协议 | `2` | 客户端与 worker 以新格式交换 Bash 文件读取记录，协议不匹配时返回 `PROTOCOL_INCOMPATIBLE` |
| 构建 ID | 源码内容哈希 | 本地与远端必须完全一致；不匹配返回 `BUILD_MISMATCH` |
| 最低 Python | `3.8` | 在加载任何源码前检查；过旧返回 `RUNTIME_UNSUPPORTED` |
| 归档格式 | `1` | 新版本不删除未知或未来格式；旧任务仍可读取 |
| 配置版本 | `1` | 新增字段提供默认值；破坏性变化才升版本 |

## 远端构建缓存

```text
~/.neverssh/
├── builds/
│   ├── .lock
│   ├── <buildId>/
│   │   ├── manifest.json
│   │   ├── build_cache.py
│   │   ├── worker.py
│   │   ├── file_ops.py
│   │   ├── workspace.py
│   │   ├── helper.py
│   │   ├── archive.py
│   │   └── .lock
│   └── .tmp-<random>/
├── sessions/
└── .archive.lock
```

- 目录 700，文件 600，拒绝符号链接；每个源文件在安装和执行前校验 SHA-256。
- 安装先写入 `.tmp-*`，校验后原子 rename；并发安装同一构建时以先完成者为准。
- worker 对 `builds/<buildId>/.lock` 持有共享锁直到进程退出。清理器持有缓存目录总锁，确认该构建已无人使用，关闭构建锁文件后才删除目录。
- 默认保留当前构建和最近 2 个未锁定构建；超过 30 天的未锁定构建也会清理。
- 缓存不可写或校验失败时返回 `BUILD_UNAVAILABLE`；正在使用的损坏构建不会被原地替换。

## A/B 与回滚

- 不同本地版本生成不同 `buildId`，可以在同一远端用户下并存。
- 新连接使用当前本地版本对应的构建；旧 worker 继续使用旧构建，互不影响。
- 回滚就是运行旧版本本地包：旧构建仍在缓存时直接复用，否则重新安装。
- 归档目录在构建之间共享；格式版本和锁保证新旧 worker 可以并存。

## 环境要求

| 能力 | 要求 | 缺失时 |
| --- | --- | --- |
| Python | 3.8+，标准库即可 | `RUNTIME_UNSUPPORTED` |
| Bash | 命令工具需要 Bash | `BASH_UNAVAILABLE` |
| Git | 可选；工作区用于检查分支和已有改动 | 在文本中说明不可用，规则、skill 和文件操作仍可使用 |
| 远端 HOME | 可写，用于 `~/.neverssh` | `BUILD_UNAVAILABLE` / `ARCHIVE_UNAVAILABLE` |
| 文件系统 | 需要支持进程间 `flock`。已验证 Linux 本地文件系统和 NFSv4.1（`local_lock=none`）。其他 NFS/SMB 配置需单独验证 | `doctor` 报告 HOME 文件系统类型 |
| SFTP | 上传/下载需要远端启用 SFTP 子系统 | `SFTP_UNAVAILABLE` |
| 本地 OpenSSH | 需要 `ssh` 和 `sftp` 客户端 | `SSH_UNAVAILABLE` / `SFTP_UNAVAILABLE` |
| 压缩 | OpenSSH `Compression=yes`，服务端可拒绝 | 自动降级，不影响正确性 |

## 发布策略

- 本地包是唯一发布物；远端不单独发布，也不需要升级服务。
- 构建 ID 由内容计算，发布物和远端缓存使用同一套源码。
- 行为修复升 patch，新增工具或字段升 minor。不兼容的接口调整在 0.x 阶段升 minor，从 1.0 起升 major。
- 发布前至少覆盖 Linux 容器矩阵：Python 3.8–3.12、OpenSSH 8/9、SFTP/无 SFTP、Bash/无 Bash、NFS HOME、压缩开/关，以及旧归档格式的清理测试。
